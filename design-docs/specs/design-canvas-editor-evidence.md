### Stall-window sync classification (session 293, design 15.3.8.15)

Each stall is recorded with page `performance.now()` start and end values. A sync sample is
stall-window when its onset page time lies inside a recorded window or its first-showing or
presentation-proxy frame is F, the first presented frame with `frameMs >= startMs`. Non-stall
samples retain p95/p99 limits of 33.4/50 ms. Stall-window samples are gated by active-set
recovery at F, no replayed ranges, no audio-domain early flashes, and beat residual at F <= 1 ms.
The generated table above reports all 11 windows for both browsers; no window or sync sample is
inferred from a latency value.

An audio-domain early flash occurs only when a presented frame shows a range while its sampled
audible time precedes that range's onset by more than one render quantum, `Q = 128 / sampleRate`.
The measured sample rate and Q are recorded in the generated results. The previous page-time
proxy remains visible as an informational count and does not gate the run. The final run has
zero global and stall-window audio-domain early flashes; the page-time proxy counts are retained
in the results table.

### Beat-drift diagnosis

The earlier publisher paired a floored 1/960-cycle runtime position with the current host time,
allowing a sub-grid phase difference up to about 2.083 ms at the workload tempo. Session 302
now pairs a running transport sample's cycle with `Clock::to_host(cycle)` when it falls within
one grid period of the current host time; otherwise the bounded fallback remains. The simulated
clock tests cover 120 bpm and a non-lattice tempo. The final Chromium and WebKit run records
0 ms beat drift and zero residual at audited stall frames.

The committed raw bundle is kept below 2 MiB. Frame, presented, onset, sync-sample, stall-audit,
and beat-residual-frame rows are serialized at 1/32; phase rows retain spans >= 50 ms. All gate
decisions, counts, and aggregate metrics use the full in-memory samples before serialization.
The summary records this sampling explicitly. Raw files are `run-001/summary.json`,
`run-001/webkit-measure.jsonl`, and `run-001/chromium-measure.jsonl`.

## Automated audio silence

Every automated browser run routes application audio through the init-script virtual sink
before the first audio connection: a pre-sink `AnalyserNode`, zero-gain stage, post-sink
`AnalyserNode`, then the real destination. Chromium also launches with `--mute-audio`. The
harness requires zero direct connections to the destination and an exactly zero post-sink peak;
the pre-sink workload must remain below the design threshold and the control must produce an
onset. The recorded pre-sink peak dBFS, RMS dBFS, onset counts and onset times are generated in
`design-docs/specs/evidence/canvas-cutover/run-001/summary.json`.

The meter uses `fftSize = 32768`, polls new samples every 100 ms, and counts a 10 ms block RMS
onset at -40 dBFS after 50 ms below -50 dBFS. The current run records those values in
`run-001/summary.json`; the harness generated them rather than this document. macOS system
volume was never read or changed, and no audio driver was installed.

## Platform limitations and recorded deviations

- WebKit clipboard, Japanese IME and touch use synthetic events. They do not establish real system clipboard, keyboard or touch hardware behavior.
- Headless browser audio may remain suspended. In that case audio and A/V sync are unavailable; measured provenance alone is eligible for the sync gate. `estimate` is reported without gating; `unavailable` is a limitation.
- The `window.__vactrPerf.counters().probe` member is currently null. Probe-specific values are therefore unavailable and do not gate this profile.
- Chromium heap is read through CDP after garbage collection. WebKit has no corresponding heap API in this harness and reports the resource ledger only.
- The iPad simulator self-check demonstrates app launch and configuration only. Its performance is not representative of a physical iPad.
- Visual synth outputs use the shipping 640x360 `RENDER_SIZE`, rather than the 15.3.7 product-profile 1024x1024 workload. This is the accepted `L-WORKLOAD-SIZE` deviation.
- Native-tier Hydra is unavailable. Native-tier and iPad video background composition are unavailable because `GlRenderHost` exists only on the browser tier (`editor/src/visual/mount.ts`).
- Audio underrun and drop counters are reported as not exposed when absent from the pinned perf API; the harness does not infer audio-thread independence from UI measurements.
- The host-reported CPAL latency can exclude CoreAudio device or safety-offset latency. Physical acoustic timing is pending.
