## Intent and Context

Prove the feature end to end in Chromium and WebKit, add the new UI to
the style gate, and run every acceptance gate on the combined tree.
Imitate `editor/test/e2e/vim-behavior.mjs:runVimChecks` (check wrapper,
`openPage`, `enableVim`, `resetDoc`, `window.__vactrPerf.doc()` and
`.selection()`), and the vim block of `editor/test/style/ui-style.mjs`.

Known lesson (VIM-40): the e2e runner serves the prebuilt `editor/dist`
and does not detect a stale build. Always run
`VACTR_REQUIRE_SESSION_ABI=1 npm run build` immediately before
`npm run e2e`, after the last source change.

## File-Level Changes

### editor/test/e2e/vim-keymap.mjs (new, budget 220 lines)

`export async function runVimKeymapChecks(browser, origin, name)` returning
`{ checks, limitations }` like `runVimChecks`. Use a fresh context with
`localStorage.setItem('vactr.vimMode', 'true')` in an init script and
`?perf=1`. Checks:
- `vim-keymap-preset`: click `.vact-vim-keymap-button`, click the
  `mise-darwin` preset button, click Apply; `localStorage['vactr.vimKeymap']`
  parses with `version` 1 and the issue list is empty; close the panel.
- `vim-keymap-kj`: seed a doc, `i`, type `ab`, then `k` `j`; doc contains
  `ab` without `k`/`j` and `.vact-vim-status[data-mode="normal"]`.
- `vim-keymap-hints`: press `Space`, wait 300 ms; `.vact-vim-hints` is
  visible, lists entries `y` and `p`, `.vact-vim-hints-summary` text is
  non-empty; `Escape` -> panel gone.
- `vim-keymap-hop`: seed `ab\ncd\nem`, `Escape`, `gg0` so the cursor is
  at 0; press `g` `j` then `m`; `.vact-vim-pending` shows
  `hop: 1 targets` (or the singular form the implementation uses; assert
  it starts with `hop`); the single target gets the first key `f`; press
  `f`; `__vactrPerf.selection().head` is 7.
- `vim-keymap-hop-off`: open the panel, set the textarea value to the
  mise-darwin text with the `hop` object's `enabled` set to false (edit
  the JSON in the page with `JSON.parse`/`JSON.stringify`, dispatch an
  `input` event), Apply; seed `ab\ncd`, cursor at 0; press `g` `j`;
  `.vact-vim-pending` does not start with `hop` and the selection head is
  3 (one line down).
Reset the keymap (panel Reset) at the end so later checks run under K0.

### editor/test/e2e/behavior.mjs (shared)

After the existing `runVimChecks` block, call `runVimKeymapChecks` in its
own try/catch pushing `{id:'vim-keymap-setup', pass:false, ...}` on a
setup error. No other change.

### editor/test/style/ui-style.mjs (shared)

In the vim page block, after the ex-row probe: press `Escape`, click
`.vact-vim-keymap-button` (panel open), take the screenshot
`${engineName}-${viewport.name}-vim-keymap@2x.png`, run the existing
`inspectPage` assertions with a viewport label suffix `-vim-keymap`, then
apply the mise-darwin preset, close the panel, press `Space`, wait 300 ms
so `.vact-vim-hints` is visible, and inspect again (`-vim-hints`). Reset
the keymap afterwards.

## Gates (run in this order on the combined tree, from editor/ unless stated)

1. `npm run check`
2. `./node_modules/.bin/vitest run test/code/vim test/canvas test/code/vim-keymap-store.test.ts test/platform`
3. Worktree root: `CARGO_TERM_QUIET=true cargo check --manifest-path editor/src-tauri/Cargo.toml` and `CARGO_TERM_QUIET=true cargo test --manifest-path editor/src-tauri/Cargo.toml`
4. Locked: `./node_modules/.bin/vitest run` (full)
5. Locked: `npm run test:style`
6. Locked: `VACTR_REQUIRE_SESSION_ABI=1 npm run build && npm run e2e -- --browser all --profile behavior --run-id vim-keymap-001 --out ../tmp/vim-keymap/VK-40/e2e/vim-keymap-001`
   (if `target/wasm32-unknown-unknown/release/vactr.wasm` is absent, prefix
   the build with `VACTR_WASM=../target/wasm32-unknown-unknown/debug/vactr.wasm`
   and note it). Every `vim-*` and `vim-keymap-*` check passes in both
   browsers.
7. Locked: `npm run e2e:examples`

Each gate has a verification record with its log under
`../tmp/vim-keymap/VK-40/attempt-<n>/`. `failureCount` must be 0.
